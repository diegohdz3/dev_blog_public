How to Make SQL Queries Inside an API.

A practical, step-by-step tutorial on connecting your API to a database and running SQL queries safely — from your first SELECT to parameterized statements.

02.2 tutorial
/ the basics

Why SQL inside APIs?

Every application that deals with data needs a way to talk to a database. Whether you're building a to-do app or an enterprise system, at some point your API needs to read, write, update, or delete data. That's where SQL comes in.

The concept is simple: your API receives a request from the client, processes it, runs a SQL query against the database, and returns the result. But doing it right — safely, efficiently, and cleanly — that's where things get interesting.

/ step 01

Setting up the connection.

First, you need to establish a connection between your API and your database. Most languages have libraries or drivers for this. For example, in Node.js you might use mysql2 or pg for PostgreSQL:

javascript db.js 
const mysql = require('mysql2/promise');

const pool = mysql.createPool({
    host: 'localhost',
    user: 'root',
    password: 'your_password',
    database: 'bakery_db',
    waitForConnections: true,
    connectionLimit: 10
});

module.exports = pool;

Using a connection pool instead of a single connection is crucial. It lets your API handle multiple requests simultaneously without opening and closing connections for each one.

/ step 02

Writing your first query.

Once your connection is set up, you can start running queries from your API routes. Here's a basic example of a GET endpoint that fetches all products from a bakery database:

javascript routes/products.js 
const express = require('express');
const router = express.Router();
const pool = require('../db');

// GET all products
router.get('/products', async (req, res) => {
    try {
        const [rows] = await pool.query(
            'SELECT * FROM products ORDER BY created_at DESC'
        );
        res.json({ success: true, data: rows });
    } catch (error) {
        console.error('Database error:', error);
        res.status(500).json({
            success: false,
            message: 'Failed to fetch products'
        });
    }
});

module.exports = router;

Notice how we wrap everything in a try/catch block. Database queries can fail for many reasons — connection timeouts, syntax errors, missing tables — and you always want to handle those gracefully instead of crashing your entire server.

/ step 03

Parameterized queries — stay safe.

This is the most important part of this tutorial. Never, ever concatenate user input directly into your SQL queries. This opens the door to SQL injection attacks — one of the most common and dangerous vulnerabilities in web applications.

"SQL injection is not a theoretical risk — it's the #1 attack vector on the OWASP Top 10. Always use parameterized queries."
javascript safe vs unsafe 
// ❌ DANGEROUS — never do this
const query = `SELECT * FROM products WHERE id = ${req.params.id}`;

// ✅ SAFE — use parameterized queries
const [rows] = await pool.query(
    'SELECT * FROM products WHERE id = ?',
    [req.params.id]
);

// For INSERT operations
const [result] = await pool.query(
    'INSERT INTO products (name, price, category) VALUES (?, ?, ?)',
    [name, price, category]
);

The ? placeholders are automatically escaped by the database driver, preventing any malicious input from being executed as SQL code.

/ step 04

Structuring your queries.

As your application grows, you'll want to organize your SQL queries properly. A common pattern is to separate your database logic into its own layer:

javascript models/Product.js 
const pool = require('../db');

class Product {
    static async getAll() {
        const [rows] = await pool.query(
            'SELECT * FROM products ORDER BY created_at DESC'
        );
        return rows;
    }

    static async getById(id) {
        const [rows] = await pool.query(
            'SELECT * FROM products WHERE id = ?', [id]
        );
        return rows[0] || null;
    }

    static async create({ name, price, category }) {
        const [result] = await pool.query(
            'INSERT INTO products (name, price, category) VALUES (?, ?, ?)',
            [name, price, category]
        );
        return { id: result.insertId, name, price, category };
    }

    static async delete(id) {
        const [result] = await pool.query(
            'DELETE FROM products WHERE id = ?', [id]
        );
        return result.affectedRows > 0;
    }
}

module.exports = Product;

This pattern keeps your routes clean and your database logic reusable. Your route handler becomes a simple call: const products = await Product.getAll();

/ final notes

Key takeaways.

  • Always use a connection pool instead of single connections.
  • Parameterize everything. Never concatenate user input into queries.
  • Wrap queries in try/catch blocks and return meaningful error messages.
  • Separate your database logic into a model layer for cleaner code.
  • Use environment variables for database credentials — never hardcode them.

SQL inside an API isn't complicated once you understand the pattern. The hard part is building the discipline to do it safely and consistently. Start simple, stay secure, and build from there.
